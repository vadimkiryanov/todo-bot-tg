# Руководство для ИИ-агента: фронтенд todo (web/)

> Фронтенд веб-приложения «todo» — мобильный PWA, отдельный сервис, не зависящий от
> Telegram-бота. Аутентификация — логин + пароль; аккаунты независимы от бота.
> Этот файл — свод правил и паттернов для работы с кодом в `web/`.
> Контракт API — в [`docs/BACKEND_API_PLAN.md`](../docs/BACKEND_API_PLAN.md).

## 1. Философия

| Принцип | Суть |
|---|---|
| **Минимализм** | Один эмодзи вместо заголовков, минимум текста и кнопок. Каждый элемент должен пройти проверку «можно ли без него?». Убрать лишнее — нормально, это приветствуется. |
| **Mobile-first** | Приложение живёт на телефоне. Проектируй под тач, не под курсор. Целевой viewport — 375px. |
| **Скорость** | Мгновенный отклик интерфейса, оптимистичные обновления, лёгкий бандл. |
| **Один источник данных** | Бэкенд — единственный источник правды (REST `/api/v1`). Фронт — тонкий клиент: рендер, кэш, UX. |
| **Дизайн как в Telegram-чате** | Верх — островок табов топиков, середина — список заметок, низ — поле ввода. Знакомый паттерн, никакой «сайтовости». |
| **Никакой магии** | Минимум зависимостей, никаких «магических» библиотек. Обычный fetch + Zustand. |

## 2. Стек (зафиксирован)

- **Vite** — сборка, dev-сервер; вход `index.html` → `src/main.tsx` → `src/App.tsx`
- **React 19** — функциональные компоненты, хуки; никаких классовых компонентов
- **Zustand 5** — глобальное состояние (единственная state-библиотека)
- **TypeScript** — `strict: true`, без `any` (кроме границ, где бэкенд отдаёт произвольные данные)
- **Tailwind CSS v4** — утилитарные классы в разметке, дизайн-токены в `app.css`
- **vite-plugin-pwa** — манифест, service worker (autoUpdate, `navigateFallbackDenylist /^\/api\//`), установка на телефон
- **Vitest** — unit-тесты (stores, api-клиент)
- **`@telegram-apps/telegram-ui`** — UI-кит в стиле Telegram; **осознанное исключение**: шторка
  настроек (`SettingsSheet`), четыре список-экрана (уведомления, таймеры, архив, выполненные),
  шторки топиков/папок (`TopicTabs`, `FolderBar`), меню действий (`MenuRow` в `InputBar`,
  `QuickMenu`, `FolderMenu`, `NoteMenu`, `TopicMenu`, `NotePage`) и дерево переноса (`MoveModal`) —
  всюду `List`/`Section`/`Cell`/`Badge`; четвёртой волной на ките и кнопки с полями ввода:
  док и панели `NotePage` (оформление, плавающая панель у выделения, «назад»), панель действий,
  бургер и плавающие кнопки `InputBar`, формы и модалки (`CreateTopicModal`, `CreateFolderModal`,
  `ReminderForm`, `SearchPanel`, `LoginView`, `ConfirmModal`) — `Button`/`IconButton`/`Input`/`Modal`
- **иконки** — из того же кита (`import { Icon24ChevronLeft } from '@telegram-apps/telegram-ui/dist/icons/24/chevron_left'`),
  но набор крошечный — 34 глифа (`find node_modules/@telegram-apps/telegram-ui/dist/icons -name '*.js'`),
  и в нём нет папки, топиков, поиска, бургера, отправки, часов, повтора, пина, глаза, шестерёнки и
  форматирования. Правило: **где библиотечный глиф есть — берём его; где нет — пишем слово, эмодзи не
  оставляем** («Пин», «Ещё», «URL», markdown-метки `B`/`I`/`#`; у `IconButton` слово читается по
  `aria-label`, у строки меню — подписью). Для «удалить» берём `Icon16Cancel`, а не `24/cancel`: у
  второго цвет вшит (`#A2ACB0`) и в красной строке меню он не краснеет
- **npm** — пакетный менеджер

Не добавлять: UI-киты, CSS-фреймворки, роутеры (react-router), другие state-библиотеки.

Исключение по UI-киту (пилот + четыре волны миграции): библиотека подключена ради шторки настроек,
четырёх список-экранов, шторок топиков/папок, всех меню действий, дерева переноса заметки, а с
четвёртой волны — ещё и всех кнопок с иконками, полей ввода форм и модалок.
Что осознанно остаётся своим (и почему):

- `SwipeStrip` — лента топиков на `embla-carousel`: **карусели в библиотеке нет вообще**, мигрировать
  некуда, а выверенная физика свайпа и «капсула за пальцем» — суть экрана;
- `TopicIsland` — `TabsList`/`SegmentedControl` библиотеки умеют только равные табы с подчёркиванием,
  островку нужны переменные ширины, капсула за пальцем, «путь в табе» и автоподкрутка ленты;
- **поле ввода чата (`InputBar`)** и **многострочный редактор заметки (`NotePage`)**: у библиотеки
  `Textarea` — форм-поле с `min-height: 84px` и подписью-лейблом (компактного многострочного
  композера нет), а `Input` однострочный и сломал бы правило «`Enter` = отправить, `Shift+Enter` =
  новая строка»; `SendButton` в 2.1.13 отсутствует. Наши `<textarea>` и `<Input>` вокруг них
  (кнопки, иконки, поле ссылки) — на ките;
- «стекло» плавающих кнопок «Папки», «Топики», «Поиск» (глифов для них в ките нет — кнопки
  подписаны словом) — наш класс `glass-fab` (`app.css` выигрывает у библиотеки по порядку
  подключения), `mode="gray"` у `IconButton` остаётся запасной заливкой под ним;
- чипы топиков в `MoveModal` — у `Chip` нет состояния «выбран» (только `elevated`/`mono`/`outline`),
  а выбранный топик у нас залит основным цветом.

Условия, без которых миграция не работает (проверено пробами):

- peer-конфликт React 19 (библиотека ждёт `^18.2.0`) снят не флагом установки, а полем
  `overrides` в `package.json` (`react`/`react-dom: "$react"`) — потому что `web/Dockerfile`
  делает `npm ci` сразу после копирования `package.json`, и `.npmrc`/`--legacy-peer-deps` там недоступны;
- стили библиотеки импортируются в `main.tsx` **до** `app.css`, чтобы `app.css` побеждал;
- `AppRoot` ровно один и живёт в `App.tsx` (`platform="ios"`): только он навешивает хешированные
  классы с токенами `--tgui--*` (в базовых стилях библиотеки их нет, как и правил на `:root`/`body`/`*`
  — протечки в другие экраны исключены). Вложенный `AppRoot` в компонентах не нужен; `Modal`
  рендерит содержимое на месте (без портала), поэтому поднятый корень покрывает и шторки;
- вне клиента Telegram библиотека не знает тему (`prefers-color-scheme` игнорирует) и берёт
  цвета из `--tg-theme-*`; мост «наши токены → библиотека» живёт в `app.css` (блок
  `@telegram-apps/telegram-ui`) и перекрывает её жёстко заданные `--tgui--card_bg_color` /
  `--tgui--tertiary_bg_color`;
- строки-`Cell` обязаны нести `w-full`: `<button>` в Chromium не растягивается как блочный бокс,
  а схлопывается по содержимому — короткая строка не занимает карточку, и обводка приоритета,
  область тапа и аксессуар (`after`: «пин» надписью, галочка) съезжают к тексту вместо правого края;
- `Cell` прокидывает `style` на корень (через `Tappable`), поэтому отступ вложенности
  (дерево папок) задаётся inline `paddingLeft` — это надёжнее утилит Tailwind: стили
  библиотеки unlayered и побеждают `@layer utilities`, для утилит пришлось бы писать
  `!important` (`px-0!` у `List`);
- `TabsList`/`SegmentedControl` для ленты топиков не годятся (равные ширины `flex: 1 0 0`,
  индикатор — подчёркивание с `translateX`): островок остаётся своим;
- строки меню — общий компонент `MenuRow` (`Cell Component="button"`, иконка набора в колонке `before`
  или слово вместо неё, подпись,
  `danger` — `text-destructive!`, `Badge` — счётчик). Меню — `List className="px-0! py-0!"` +
  `Section`: собственные отступы списка (`10px 18px` на iOS) снимаются, поля задаёт карточка-панель;
- **пункты `Section` — только реально отрисованные элементы**: разделители `<hr>` расставляются по
  индексам детей, а фрагмент (`<>…</>`) считается одним ребёнком, и внутри него строки идут без
  разделителей; условие же (`{cond && <MenuRow/>}`) занимает слот даже когда ложно — получаются
  `<hr>` подряд. Поэтому условные пункты собираются массивом `ReactNode[]` с `key` и передаются
  как `{rows}` (см. `NoteMenu`, `NotePage`);
- кнопки и поля (волна 4). `IconButton`/`Button`: `type` задаём явно (`IconButton` его не ставит — внутри
  формы кнопка стала бы `submit`), `disabled` библиотека не стилизует (наш `disabled:opacity-*` остаётся),
  `loading={busy}` заменяет ручной `{busy ? <Spinner/> : …}`. Тач-цель возвращается оверрайдами:
  `size="m"` + `h-11 w-11 items-center justify-center rounded-full! p-0!` (компактные — `size="s"` +
  `h-8 w-8 rounded-lg! p-0!`), высота — `h-11!`/`h-10!` (у библиотеки 42/50). Заливки — режимами:
  `gray` — бывш. `bg-muted`, `bezeled` — бывш. акцентная/включённое состояние, `plain` — прозрачная,
  `outline` — с рамкой; сплошной акцент или красный — `plain` + `bg-primary!`/`bg-destructive!` +
  `text-white!`. Подпись `Button` обёрнута в свою типографику, поэтому `text-xs!` на кнопку не действует
  (кегль задаёт `size`). Отдельная ловушка: базовые классы библиотеки лежат вне `@layer` и бьют наши
  утилиты, поэтому `position` на компоненте библиотеки пишем с `!` (`absolute!`/`fixed!` — `Tappable`
  ставит `position: relative`, иначе кнопка встаёт в поток панели), а рамку на `IconButton` — `border!`
  (у неё `border: none`);
- `Input`: `value`/`onChange`/`ref`/`placeholder`/`type` уходят во внутренний `<input>`, а `className` —
  на внутренний `<label>` (там заливка, радиус, `min-height: 48px`), поэтому, чтобы поле тянулось в
  строке, его оборачивают в `<div className="min-w-0 flex-1">`. Заливка библиотеки — `--tgui--bg_color`
  = наш `--color-background`, на фоне страницы поле было бы невидимым: конвертированным полям нужен
  `bg-muted!`. Нативные `<select>` и даты остаются своими — библиотечные `Select`/пикеры это отдельный заход;
- цена: подключение библиотеки — +7.2 kB JS / +45.6 kB CSS (gzip +3.8 / +10.3), CSS библиотеки не
  tree-shake'ается; после волны 4 (кнопки, иконки-компоненты, поля ввода) в сборке ≈107 kB CSS
  (gzip ≈21.4 kB) / ≈426 kB JS (gzip ≈127 kB).

## 3. Структура директорий

```
web/
├── public/
│   └── icons/                 # PWA-иконки 192, 512, 180
└── src/
    ├── main.tsx               # bootstrap + registerSW
    ├── App.tsx                # корень: guard-роутер, переключатель экранов
    ├── app.css                # Tailwind-вход, токены, кастомные классы
    └── lib/
        ├── api/               # ВСЕ сетевые вызовы (клиент + по сущностям)
        ├── stores/            # Zustand-сторы (по одному на сущность)
        ├── types/             # типы API (зеркало DTO бэкенда)
        ├── utils/             # чистые функции (форматирование, блоки, click) и хуки
        │                      #   (longPress — долгий тач/правый клик, press — отклик нажатий)
        ├── router.ts          # микро-роутер (useRouteStore, navigate, replacePath)
        ├── views/             # экраны: LoginView, ChatView, ArchivedView, DoneView,
        │                      #   TimersView, NotificationsView
        └── components/        # UI-компоненты (PascalCase.tsx)
```

**Категорически запрещено:**
- `helpers/`, `common/` — у каждого кода есть своё место в `lib/`
- Сетевые вызовы (raw fetch) вне `lib/api/`
- Циклические импорты между stores
- Импорт компонентов с расширением (`.tsx` опускается): `from '../components/NoteCard'`

## 4. Соглашения по коду

### 4.1 React-компоненты

```tsx
interface NoteCardProps {
  note: Note;
  onOpen: (note: Note) => void;
  highlighted?: boolean;
}

export function NoteCard({ note, onOpen, highlighted = false }: NoteCardProps) {
  // ...
}
```

- Каждый компонент — **именованный экспорт** функции; интерфейс `XxxProps` — рядом
- Маппинг рун из Svelte 5: `$props` → props-интерфейс, `$state` → `useState`, `$derived` →
  вычисление/`useMemo`, `$effect` → `useEffect` (+cleanup), `onMount` → `useEffect([], ...)`,
  `bind:this` → `useRef`, `on:event` → `onEvent`, `{#if}`/`{#each}` → условный рендер / `list.map`
  с `key`, `{#snippet}`/`{@render}` → локальные функции, возвращающие JSX (вызывать как
  функции, не как `<Comp/>` — иначе remount), `goto` → `navigate`, `{@const x}` → переменная
  в map-колбэке
- Ссылки на DOM — `useRef`; таймеры `window.setTimeout` типизировать явно как
  `useRef<number | undefined>` (тип `number`, не `ReturnType<typeof setTimeout>` — иначе
  @types/node резолвит `NodeJS.Timeout`)
- Локальные scoped-стили из портированных `.svelte` переносятся в конец `src/app.css` блоком
  с маркером `/* <Name>: scoped-стили из <Name>.svelte (портированы в React) */`; `:global()`
  разворачивается

### 4.2 Zustand

```ts
// lib/stores/topics.ts
interface TopicsState {
  topics: Topic[];
  loading: boolean;
  error: string | null;
}

export const useTopicsStore = create<TopicsState>()(() => ({
  topics: [],
  loading: false,
  error: null,
}));

export function loadTopics(): void { /* useTopicsStore.setState(...) */ }
```

- Стор: `create<State>()(() => ({...}))`; **действия — export-функции** (не методы стора),
  мутируют через `useXStore.setState(...)`; `getState()` — только в обработчиках событий,
  siema-колбэках и runtime-функциях (защита от stale closures), не в рендере
- В компонентах — **только селекторы** `useXStore((s) => s.field)`; ui-флаги — через
  `useUiStore.setState({...})`
- `setState` асинхронен (батчинг) — синхронное чтение сразу после записи идёт через
  ref-зеркало или `getState()`
- Мутации списков — через store-функции с оптимистичным обновлением:
  применить → запросить API → при ошибке откатить и показать ошибку
- Тесты стора — `*.test.ts` рядом, с `resetXStore()`/свежим стором в `beforeEach`

### 4.3 Роутинг

- Микро-роутер `lib/router.ts`: `useRouteStore` (поле `path`), `navigate(path)` (pushState),
  `replacePath(path)` (replaceState), `initRouter()` (popstate, cleanup), `currentPath()`
- Query (`?topic=&folder=&note=`) роутер не трогает — им управляет `ChatView` через history
- Guard'ы в `App.tsx`: гость на защищённом пути → `replacePath('/login')`, авторизованный
  на `/login` → `replacePath('/')` (паритет с бывшими SvelteKit `load`-redirect'ами)

### 4.4 TypeScript

- `strict: true`; типы API в `lib/types/api.ts` — зеркалят DTO бэкенда (обновлять при изменении контракта)
- Опциональные поля бэкенда (nil) — `foo: number | null`, не `foo?` без причины
- `verbatimModuleSyntax`: типы импортируются через `import type { ... }`

### 4.5 Стили

- Утилиты Tailwind в разметке; кастомные стили — только в `app.css`
  (дизайн-токены `@theme` из Tailwind v4 + классы `island-glass`, `glass-menu`, `glass-fab`,
  `glass-sheet`, `sheet-*`, `backdrop-*`, `note-priority-*`, `loader`, `empty-bob`, `text-muted`,
  `scroll-area` и др. — использовать их, не дублировать)
- Цвета приоритетов — токены `--color-priority-*` (кольцо `note-priority-*`); различимы и в тёмной теме
- Нижняя панель ввода всегда учитывает `env(safe-area-inset-bottom)`
- Единственное место, где стили заданы не нами — компоненты `@telegram-apps/telegram-ui`
  (шторка настроек, список заметок чата и результаты поиска, списки уведомлений/таймеров/архива/
  выполненных, шторки топиков и папок, меню действий, дерево переноса, кнопки с иконками, поля
  ввода форм и модалки);
  их цвета идут через `--tgui--*`, который библиотека выводит из `--tg-theme-*`. Эти переменные
  заполняются в `app.css` ссылками на наши токены (`--tg-theme-bg-color: var(--color-background)`),
  поэтому тема библиотеки переключается вместе с приложением. Правки — только в том блоке `app.css`,
  иначе тема развалится
- Поверх библиотечных строк свои классы остаются рабочими и нужными: `btn-press-soft` (отклик на
  нажатие), `note-priority-*` (кольцо приоритета — на строке-Cell оно рисуется по контуру карточки),
  `note-preview`/`note-preview-full` (обрезка превью), `note-done` (зачёркнутая выполненная)

### 4.6 API-клиент

```ts
// lib/api/client.ts — единственная точка fetch
export class ApiError extends Error { ... }
```

- Каждый эндпоинт — функция в `lib/api/<entity>.ts` (`listTopics()`, `createNote(dto)`, …)
- `credentials: 'same-origin'` (cookie-сессия)
- Ошибка: `ApiError` со статусом; `401` — сигнал для session store (возврат на логин)
- Формат ответа/ошибки — строго по `BACKEND_API_PLAN.md`

### 4.7 Обработка ошибок

- Ошибки API — `ApiError`; текст из `{"error": ...}` показывать пользователю как есть (он уже на русском)
- Сеть недоступна: `navigator.onLine` + единый компонент «нет сети» (не падать, не терять состояние)
- Никаких `console.log` в проде; `console.error` — только для неожиданных ошибок

## 5. UX-принципы (обязательны)

1. **Одна иконка вместо заголовков** — `Icon28Edit` в пустом топике, без текста «для красоты»
   (эмодзи в интерфейсе не используем — см. правило иконок в §2).
2. **Карточки-кнопки** — заметка/топик = отдельная карточка с превью. Никакой нумерации.
   В четырёх списках на `telegram-ui` (уведомления, таймеры, архив, выполненные) и в шторках
   топиков/папок та же идея выражена строкой-`Cell` внутри карточки-секции: превью в несколько
   строк, мета — подписью (иконка напоминания · дата правки), приоритет — кольцом по контуру строки,
   пин — надписью small-caps у правого края (глифа пина в ките нет). Тот же `NoteCell` рисует и
   заметки чата — стеклянных карточек (`NoteCard`) в проекте больше нет.
   Шторки выглядят одинаково: активный элемент — галочкой, счётчик заметок — серым бейджем,
   вложенность папок — отступом всего ряда, долгий тач — меню (`useLongPress(onTrigger, holdMs)`,
   в шторках 500 мс: жест соседствует со свайпом ленты).
3. **Расположение как в чате**: верх — островок табов топиков, середина — список заметок
   (свайп между топиками, внутри папок свайп «назад»), низ — поле ввода
   (`Enter` = отправить, `Shift+Enter` = новая строка).
4. **Тач-цели ≥ 44px**, нижняя панель действий, `env(safe-area-inset-bottom)`.
5. **Быстрые действия без лишних шагов**: «выполнить» / приоритет — одним тапом, с оптимистичным откликом.
6. **Не перегружать** — если элемент не несёт информации, его нет. Это требование владельца проекта.
7. Сортировка приходит с бэкенда (закреплённые → приоритет → выполненные в конце) — фронт не дублирует.

## 6. PWA-требования

- Манифест и SW — в `vite.config.ts` (`VitePWA`, `registerType: 'autoUpdate'`)
- Иконки 192/512 + apple-touch 180 генерируются `npm run gen:icons` (sharp) в `public/icons/`
- `index.html`: `viewport-fit=cover`, theme-color для светлой/тёмной темы
- SW не должен перехватывать `/api/*` (вход через Telegram-виджет) — `navigateFallbackDenylist`

## 7. Тестирование

- Vitest: stores (мутации, оптимистичные откаты), api-клиент (мок fetch); среда `node`,
  `VITE_USE_MOCK=true` принудительно (в `vite.config.ts`)
- Прогон перед сдачей: `npm run check` (tsc --noEmit), `npm run test`, `npm run build`
- После крупных изменений — Lighthouse (mobile): производительность ≥ 90, PWA installable

## 8. Антипаттерны

| Антипаттерн | Как надо |
|---|---|
| Raw fetch в компоненте | Только через `lib/api/` |
| `any` в коде | Типы в `lib/types/api.ts`, сужение через guards |
| `useXStore.getState()` в рендере | Селекторы `useXStore((s) => s.field)`; `getState()` — в обработчиках |
| Логика бизнес-правил на фронте | Правила (сортировка, валидация) — на бэкенде; фронт рендерит как есть |
| Дублирование состояний | Один стор на сущность; производные — через селекторы/`useMemo` |
| «Красивый» текст-заголовки | Иконка кита (или слово), минимум слов |
| Тяжёлые библиотеки ради одной фичи | Написать 20 строк самим (исключение — `telegram-ui`: список заметок чата, четыре список-экрана, шторка настроек, шторки топиков/папок, меню действий, дерево переноса, кнопки с иконками, поля ввода форм и модалки, см. §2: цена посчитана; расширять только по решению и отдельным заходом) |
| Игнор безопасных зон экрана | `safe-area-inset` для нижней панели |
| Расхождение типов с API | Обновить `types/api.ts` сразу при изменении контракта |
