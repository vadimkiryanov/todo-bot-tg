# План: веб-приложение todo (фронтенд)

> Документ для ИИ-агента: последовательный список этапов и задач.
> Каждый этап — самодостаточная порция работы с критериями готовности (Definition of Done).
> Идти строго по порядку: следующий этап начинается только когда закрыт предыдущий.

## 1. Контекст и цель

Существующий `todo-bot-tg` — личный таск-менеджер, работающий как Telegram-бот (Go, PostgreSQL).
Вся бизнес-логика изолирована в сервисном слое (`internal/service/todo`) и завязана на `userID int64`.

**Цель:** веб-приложение (PWA) как **отдельный сервис**, не зависящий от Telegram-бота.
Приложение доступно в первую очередь с мобильных устройств, сохраняется на телефон
(«Add to Home Screen»). Первая версия — **прототип**: аутентификация, топики, заметки.

**Зафиксированные решения (согласованы с владельцем, 2026-08-21):**

| Решение | Выбор |
|---|---|
| Аутентификация | **Логин + пароль** (регистрация и вход; НЕ Telegram Login) |
| Аккаунты | **Независимые от бота**: веб-регистрация создаёт отдельного пользователя в той же БД; бот и веб не видят данные друг друга |
| Объём MVP | Топики + заметки. Папки, напоминания, вложения, настройки, закрепление — позже |
| Дизайн | Максимально близкий к Telegram-чату: верхняя панель — табы топиков, средняя — список заметок, нижняя — поле ввода |
| Структура репо | Монорепо: фронт в `web/`, бэкенд остаётся в корне |
| Деплой | Один домен: `/` — SPA, `/api/*` — REST (позже) |

**Изменения бэкенда** — описаны отдельно в [`BACKEND_API_PLAN.md`](BACKEND_API_PLAN.md).
Фронтенд и бэкенд разрабатываются как два независимых сервиса; API-контракт — в `BACKEND_API_PLAN.md`.

## 2. Стек

| Компонент | Технология | Почему |
|---|---|---|
| Сборка | Vite 6+ | Быстрый dev-сервер, HMR, современный дефолт |
| UI | Svelte 5 (runes: `$state`, `$derived`, `$effect`) | Минимальный бандл, реактивность, быстрая разработка |
| Язык | TypeScript (strict) | Контракт с API, безопасный рефакторинг |
| Стили | Tailwind CSS v4 (`@tailwindcss/vite`) | Utility-first, mobile-first, без лишнего CSS |
| PWA | `vite-plugin-pwa` (Workbox) | Manifest, service worker, установка на телефон |
| Тесты | Vitest (unit) | Лёгкий запуск, интеграция с Vite |
| Пакеты | npm | Есть везде |
| Node | 22 LTS | Текущая LTS |

**Сознательно НЕ берём:**
- SvelteKit — приложение одноуровневое (чат-экран + оверлеи), SSR не нужен.
  Навигация — state-based через стор, без роутера.
- Сторонний роутер, UI-кит, state-библиотеки — хватает `$state` и plain stores.
- CSS-фреймворки — Tailwind v4 + дизайн-токены.

## 3. Дизайн (как в Telegram-чате)

Приложение — один экран в духе чата:

```
┌──────────────────────────────────────┐
│ [🏠 Все] [Топик1] [Топик2] [＋]      │ ← ВЕРХНЯЯ панель: табы топиков
├──────────────────────────────────────┤
│ 📌 Закреплённая заметка              │
│ 🔴 Высокий приоритет                 │
│ 🟡 Средний приоритет                 │
│ ✔ Выполненная заметка (зачёркнута)   │ ← СРЕДНЯЯ панель: список заметок
│ …                                    │
│                                      │
│                                      │
├──────────────────────────────────────┤
│ ✏️ Написать заметку…            ➤    │ ← НИЖНЯЯ панель: поле ввода
└──────────────────────────────────────┘
```

- **Верхняя панель** — горизонтально скроллящаяся строка табов топиков (активный подсвечен)
  + кнопка «＋» (создать топик). Долгий тап по табу — переименовать/удалить топик.
- **Средняя панель** — список заметок активного топика (как сообщения в чате),
  тап по заметке открывает оверлей с действиями.
- **Нижняя панель** — поле ввода с кнопкой отправки: `Enter` = отправить,
  `Shift+Enter` = перевод строки. Прилипает к низу, учитывает `safe-area-inset-bottom`.

## 4. Принципы UX (обязательны, выстраданы на боте)

1. **Минимализм.** Один эмодзи вместо заголовков, минимум текста и кнопок.
   Каждый элемент оправдывает себя вопросом «можно ли без него?».
2. **Карточки-кнопки.** Заметка/топик — отдельная карточка с превью. Без нумерации.
3. **Mobile-first.** Целевой экран — смартфон (375px). Тач-цели ≥44px, работа одной рукой,
   `env(safe-area-inset-*)`.
4. **Мгновенная реакция.** Оптимистичные обновления для быстрых действий (✅, приоритет),
   откат при ошибке.
5. **Минимум шагов.** Создание заметки: текст → сразу в списке. Никаких мастеров.
6. Сортировка как у бота: закреплённые 📌 сверху → 🔴 → 🟡 → без → 🔵, выполненные в конце.

## 6. Экраны и навигация

- `LoginView` — вход/регистрация (переключатель режимов).
- `ChatView` — основной экран (табы + список + поле ввода).
- `NoteOverlay` — оверлей поверх чата (полный текст, действия).

Навигация state-based: `navigation` store хранит `{ screen: 'login'|'chat', activeTopicID }`.
Никакого роутера: переключение экранов — условие в `App.svelte`.

- [ ] Дизайн-токены в `app.css` (`@theme`): цвета, радиусы, отступы, шрифт; светлая тема
- [ ] Настроить скрипты: `dev` / `build` / `preview` / `check` (svelte-check + tsc) / `test` (Vitest)

### Этап 1. Аутентификация (логин + пароль)

Требует бэкенд: `POST /api/v1/auth/register|login|logout`, `GET /api/v1/me`.

- [x] `api/client.ts`: базовый fetch (`credentials: 'same-origin'`), `ApiError` со статусом, текст ошибки из `{"error": ...}`; при `401` — сброс сессии
- [x] `api/auth.ts`: `register(username, password)`, `login(username, password)`, `logout()`, `me()`
- [x] `types/api.ts`: `User`, `Topic`, `Note` (зеркало DTO бэкенда)
- [x] `LoginView`: переключатель «Вход / Регистрация», поля username/password, валидация (username 3–32, password ≥8), ошибки сервера под полями
- [x] `session` store: статус `{ state: 'loading'|'guest'|'authed', user }`; при старте — `GET /me`
- [x] После входа — переход в `ChatView`; кнопка «Выйти» (долгий тап по шапке)
- [x] При `401` на любом запросе — возврат на `LoginView` без потери введённого

**Done:** полный цикл регистрация → вход → выход, сессия переживает перезагрузку страницы.
